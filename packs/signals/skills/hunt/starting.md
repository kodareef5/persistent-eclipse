# Start a desk, then improve it

The [desk stories](desks.md) describe the responsibility. The scopes show good
starting shapes to draw on; SCOPE records the operator's actual choices. A
small team can alternate responsibilities across time instead of assigning one
permanent worker to each function.

| Opportunity | Build only what helps | Check before expanding |
| --- | --- | --- |
| Useful recurring service | A bounded field/watchlist, a few public sources, a report with a clear audience | Is the report useful and the coverage honest? |
| One small collector | Save source identifiers, URLs, publication/retrieval times, and relevant observations | Does it reduce repeated work; are gaps visible? HN has a working example |
| Change detection | Compare meaningful passages or fields; queue material differences for review | Can it separate substantive changes from formatting, reposts, and noise? |
| Relationships and specialties | Trace entities, dependencies, audience questions, authority or treatment prerequisites | Is each relationship supported; does breadth still receive attention? |
| Feedback and transfer | Review useful findings, misses, failed methods, and source roles | Can another investigation reuse the method without assuming the old conclusion? |
| Optional instruments | Forecast resolvable questions; use independent comparisons for difficult choices | Is the instrument improving judgment enough to justify its cost? |

These are possibilities, not stages to complete. Follow the mission and evidence;
feedback begins with the first useful result. Proposed collectors for filings, dockets,
accounting data, or search performance are project ideas, not tools shipped here.
Build one small script when a repeated need earns it; avoid creating a generic
scraping service to accommodate imagined future requirements.

Start from the operator's objective and any delivery commitments. If a recurring
service is requested, agree what arrives, for whom, and when. Keep room for deep
research and useful method improvements. When capacity cannot cover the
commitments, explain the tradeoff.
