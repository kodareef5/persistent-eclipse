access route with what it can reveal and how it can mislead. The catalog is a
starting point, not a promise that every endpoint currently works in every lab.

## One baseline, meaningful updates

Initial catalog baseline: **2026-10-31**, inherited from the original v0.1 checks.
The original text described checks from one ordinary connection without API keys;
it did not retain reproducible receipts for every route. Treat those entries as
historical starting knowledge, not a newly verified service contract. Inherited
quotas, access requirements, and endpoint details may need rechecking before use.

Git records ordinary edits. Add to [UPDATES.md](catalog.updates.md) only for a useful new
capability, corrected interpretation, revalidation worth retaining, or access
failure that changes a lab's approach. A commit such as
`resource(github-stars): add historical attention route` makes history searchable.
Do not bump a catalog-wide “checked” date after editing a row.

A material update identifies the resource, finding, research implication, and
supporting documentation or receipt. Distinguish **documentation checked**, **live
request checked**, **historical observation**, and **untested lead**. Keep receipts
when a validation claim matters: date/time, request or command, access/auth mode
without credentials, relevant environment, status, and enough output to check the
claim. Do not log secrets or private source material in a shared note or a proposal.

## Limitations versus incidents

Keep durable interpretation limits in the source row: a patent is not a product,
a sponsor's trial record is not an independent outcome, and an award ceiling is
not spending. Attribute temporary failures to their context. A 403, 429, challenge,
or connection failure from one host does not establish a universal access rule.
Check official access guidance and retry appropriately before relying on a route.

The baseline incidents are summarized in UPDATES; original detail remains in Git.
A successful request also has limits: one response does not test pagination,
coverage, sustained access, or availability from another environment.

## Make discoveries cumulative

Maintain lab-specific source performance in PE, then propose reusable lessons to
this catalog or the field guides. Recognize sources that originate, corroborate,
challenge, or contextualize useful ideas separately from those that repeat them.
Use [source-intelligence methods](sources.md); do not
reduce discovery value to a forecast score or create a scorecard for every feed.

Catalog history describes our knowledge of a resource. Research evidence dates
describe observed events and retrieved versions. Monitoring receipts describe
actual successful checks. Preserve all three meanings without substituting one
for another.
